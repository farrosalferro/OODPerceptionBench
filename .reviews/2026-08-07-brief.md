## What the implementing agent says it did

Two components of a CARLA autonomous-driving benchmark release, both authored by Claude
sub-agents across several sessions, then repaired by a later Claude pass.

**records/** — generates the released per-route baseline records from ~498k result JSONs
(seed 42 only). Output is 8550 rows x 64 columns, CSV + parquet. `reproduce_table1.py`
regenerates the paper's headline table from it. The paper reports N=17 models, 51
(model,category) cells, K=12/17 visually robust, 14/17 with significant geometric regression,
46/51 cells geometric-deeper, a=4.93, b=13.221, paired Cohen's d_z=1.14.

A later repair moved a blueprint-ID rename (`vehicle.caterpillar.dumptruck` ->
`vehicle.ood.dumptruck`, six vehicles) *inside* `build_records.py` via `apply_rename()`, so the
shipped artifact is reproducible from shipped code. `apply_rename()` guards that it runs AFTER
`attribute_ood_collisions()`, because raw collision messages carry pre-rename IDs and renaming
first would silently zero the OOD-collision metric. `validate_against_frozen.py` declares
exactly 2910 expected rename deltas and fails if the count is too low as well as too high.

**runner/** — a portable evaluation runner (local multi-GPU pool + SLURM backend) replacing
cluster-specific orchestrators. Config-driven, no hardcoded paths. A prior pass fixed five
defects: (1) a failed launch destroyed the checkpoint it was about to replace; (2) Ctrl-C
charged the interrupted route's infra retry budget; (3) `slurm.max_parallel` never gated
concurrency; (4) `_settle` still charged budget on interrupted attempts reaching a final state;
(5) `gpus:` validation deduped only the CUDA index, not the Vulkan adapter.

## Deliberately out of scope

- The runner has **zero hardware validation**. No CARLA has ever run against it. 125 unit tests
  pass with no GPU. Do not report "untested against real CARLA" as a finding — it is known and
  documented in `runner/STATUS.md`, which lists 10 hardware-only items (H1-H10).
- No acceptance goldens exist; the acceptance harness deliberately exits INCONCLUSIVE.
- `records/` data artifacts (CSV, parquet, `rename_map.json`) are excluded from the diff — they
  are outputs, not code.
- The change set was **reconstructed from git**, not from the snapshot hook: these components
  were authored across multiple sessions, so the hook held only the most recent repair pass.
- Docs/markdown in the diff are context; the review target is Python and shell.

## The claim this code supports

`records/` produces **the numbers in the paper** — every value in Table 1 and the abstract. A
metric-definition slip, a bad join, a silent row drop, or a rename applied at the wrong point in
the pipeline propagates directly into published claims about 17 models, and nothing downstream
would catch it.

`runner/` produces **other researchers' numbers**. It is the entry point by which third parties
evaluate their own models on this benchmark. A resume bug, a port/GPU collision, a partial sweep
exiting 0, or a worker-dependent seed path yields plausible-looking but wrong results for
anyone who uses it.
